# M8 whole-repository review

Review scope: all M0–M7 application code, SQL migrations/permissions, ingestion/analytics, durable work/alerts, care and guardian flows, data rights, browser UI and CI/tests. The `codex review` command received that explicit whole-repository scope, not just the working diff. It was instructed to be read-only, avoid credentials/live mutations/external accounts and not delegate. The configured reviewer reported no actionable findings. That is not a proof of correctness; independent fault-injection checks below found a bug it missed.

## Independently verified corrections

1. **Duplicate clinical writes after an uncertain response.** `DoctorTeam` and `ConsultRoom` generated a fresh UUID on every submit, defeating the database's existing idempotency checks. A Playwright route let the real server commit, then aborted its response. Before the fix, retrying created two consults; the assertion expected one and received two. The UI now retains the operation ID for unchanged retries. A confirmed message write clears its draft before refreshing the view, so a failed refresh does not offer the same message as an unsent draft. Regression coverage checks exactly one consult and two total messages after lost-response retries.
2. **Unvalidated doctor pagination links.** The server page directly parsed untrusted JSON/UUIDs and accepted incomplete record cursors. Complete schemas now preserve exact timestamps and reject missing, malformed, repeated or extra cursor fields. Unit cases cover these boundaries; the live doctor browser flow checks controlled 404s and the API's 400 response.
3. **Push configuration wording.** The environment template now says explicitly that VAPID fields do not enable the unimplemented server-push transport, matching the README and OQ004.
4. **Live benchmark deadline.** An otherwise error-free streaming re-import reached 570,000/620,285 records when its hard-coded 400-second test timeout expired. An uninterrupted retry then reached 511,000 records before the initial ten-minute replacement expired. D019 records a fifteen-minute bounded allowance plus a two-minute no-progress watchdog. No size, memory, count, deduplication or production-timeout requirement was relaxed, and failed attempts are not counted as verification.

No database migration or permission expansion was needed for these corrections. No review finding was suppressed and no tests were permanently skipped or removed. Filtered diagnostic runs are not counted as full verification. PROGRESS.md records the failed attempts separately from the eventual clean evidence. The large ingestion test subsequently passed twice in one uninterrupted 36.7-minute run, and the full shorter verification matrix passed twice. OQ008 was therefore resolved and removed rather than retained as a launch question.

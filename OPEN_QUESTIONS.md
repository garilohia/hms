## OQ017 — Managed extension and password-security warnings

- Production's security advisor flags `pg_net` in `public`. The installed 0.20.4 extension is owned by `supabase_admin` and non-relocatable; its 28 members actually live in `net`. Do not drop/recreate it or edit catalogues to silence the warning: the active minute dispatcher depends on it. [pg_net control](https://github.com/supabase/pg_net/blob/master/pg_net.control.in), [PostgreSQL relocation rules](https://www.postgresql.org/docs/17/sql-alterextension.html).
- A zero-row PostgREST probe on 19 September returned 406/PGRST106 for `Accept-Profile: net`, confirming it is not API-exposed. Keep `net` excluded. `PUBLIC`-inherited SQL privileges still allow browser roles to use its functions/tables; this is a defence-in-depth gap, not a clean advisor result. [Schema exposure](https://supabase.com/docs/guides/api/using-custom-schemas).
- Obtain Supabase's supported owner-level least-privilege procedure before changing those grants. The worker and scheduled job run as `postgres` and currently rely on `PUBLIC` grants; ordinary `postgres` lacks the extension owner's schema grant option. A blanket revoke risks breaking scheduling and managed webhooks, while revoking only named browser roles leaves their inherited rights. No privilege bypass or destructive extension operation was attempted. [Restricted superuser roles](https://supabase.com/docs/guides/database/postgres/roles-superuser), [pg_net](https://supabase.com/docs/guides/database/extensions/pg_net).
- Leaked-password protection is also disabled. The application uses magic links, but that does not establish that all password endpoints are disabled. Review password-auth exposure and enable protection on an eligible plan if password flows are introduced. No paid plan was enabled. [Password security](https://supabase.com/docs/guides/auth/password-security).
